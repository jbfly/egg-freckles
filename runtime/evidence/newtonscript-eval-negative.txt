NewtonScript evaluation result-channel investigation — corrected MAIN rerun, 2026-07-26

Why this supersedes the earlier negative
----------------------------------------
The earlier investigation used only SCRATCH (127.0.0.1:18090), where no script
was ever proven to execute. Its absence of evaluator output could not establish
whether a working evaluator had a result channel.

This rerun used only MAIN (127.0.0.1:18080).

Required execution baseline
---------------------------
MAIN visibly executed:

  GetRoot():Notify(3, "MAIN baseline", "evaluator runs");

The endpoint replied `queued`, and the screen changed to a notification headed
"MAIN baseline". Evidence:

  runtime/evidence/newtonscript-main-working-evaluator.png
  runtime/evidence/newtonscript-main-working-evaluator.txt

An undefined symbol also visibly executed and produced Newton error -48807:

  runtime/evidence/newtonscript-main-undefined-error.png
  runtime/evidence/newtonscript-main-undefined-error.txt

Output-channel result
---------------------
A `podman logs --since 0s -f` capture was started from a verified zero-byte
file. MAIN then received a visibly executing notification, `2+2`, and
`PonytailUndefinedProbe`. MAIN was restarted to terminate Einstein and force
buffered process output to flush before the follower was stopped.

The capture contains the three HTTP request lines and restart diagnostics, but
no returned value, `Exception`, Newton error, marker, or evaluator print:

  runtime/evidence/newtonscript-main-buffer-flush.log

Three caller-visible cases
--------------------------
Exact timings and responses are in:

  runtime/evidence/newtonscript-main-three-cases.txt

  `2+2`                    -> HTTP 200, queued (not 4)
  `PonytailUndefinedProbe` -> HTTP 200, queued (screen showed -48807)
  `while true do nil`      -> HTTP 200, queued (no bounded outcome)

MAIN was restarted after the blocked-evaluation probe. The three outcomes are
not distinguishable through the current endpoint.

Implementation decision
-----------------------
No code was committed. The proposed synchronous tagged log scraper depends on
an evaluator result or exception line reaching process output. On a demonstrably
working MAIN evaluator, neither line appeared, including after forced buffer
flush. Implementing the scraper would therefore return timeout for all three
cases and repeat the previous candidate's failure.

The remaining viable direction is an explicit Newton-side completion signal to
the host carrying either the result or CurrentException().
