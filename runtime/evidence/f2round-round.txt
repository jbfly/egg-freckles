What A7 is
----------
Chat A4 plus three buttons in a second control row and one hideable overlay:

    Ask Note   newest stock note -> the prompt, on the normal chat path
    Save Note  the last agent reply -> a new native note (MakeTextNote+NewNote)
    Ink        shows the capture canvas over the chat; Clear/Undo/Send/Chat

Two plain buttons instead of a toggle: nothing to remember, nothing to read
back off a 1997 screen, and both directions are one tap. `Save Note` writes
whatever the last reply was, so it also saves an ink reading.

The note bridge no longer speaks HTTP. `Ask Note` reads the soup and calls the
same Send() a typed prompt calls, so a note over 227 characters splits into
MSGP parts. That is the death of `No answer: LENGTH` (docs/notes-bridge.md).

Three defects this round found, all of them in code that was called "proven"
----------------------------------------------------------------------------
1. **`cursor:ResetToEnd()` lands ON the last entry and returns it.** The
   note-export idiom `ResetToEnd(); Prev()` therefore reads the **second**
   newest note. Measured directly:

       local a := c:ResetToEnd(); local b := c:Entry();
       => "reset=3 entry=3"          while c:Prev() gave 2

   Soup at the time: `0/64461125/nil 1/64462106/nil 2/64464021/nil 3/64477232/1`
   — the a5 build read entry 2 (a data=nil seed note) and said "Newest note has
   no text" (runtime/evidence/f2round-03-asknote.png), and its Save Note
   readback reported `id=3` for an entry that was really `id=4`
   (runtime/evidence/f2round-08-savenote.png). Fix: use ResetToEnd's return
   value. This is a real bug in the shipped NoteExportN13 create/read paths.

2. **Two NIE links at once is not the way.** The a5 build dropped the chat link
   (`:Stop()`) and immediately re-grabbed one for the ink POST; `connect` then
   failed with **-16009** — "Phone connection was cut off, or invalid call when
   not connected" (refs/NewtonProgrammerRef20.txt:73102). Screen:
   runtime/evidence/f2round-06-ink-sending.png. Fix: the ink endpoint rides the
   NIE link the chat already holds — one link, two connections, and the chat
   session is never interrupted.

3. **A slot named `inkOpen` shadowed the method `InkOpen`** — symbols are
   case-insensitive, so every ink Send threw **-48200** before it reached the
   wire (runtime/evidence/f2round-14-ink-thinking.png, a6 build). Exactly the
   trap the A2 round hit with `transcriptTail`. The slot was write-only; it was
   deleted rather than renamed.

Two smaller things
------------------
- `vfFrameBlack` alone draws no frame (the frame pen width is zero without
  `vfPen`), so the canvas box was invisible on a5/a6. Two `protoDivider` rules
  mark the writing area instead — the same thing InkPad2 did.
- `vfFillWhite` on the overlay is what makes it opaque; that part works.
- Overlay mechanics: `Show()` only works on a view that was opened and then
  hidden, so the panel ships `vVisible` and is hidden by a 150 ms delayed call.
- A stray `-48601` (Syntax error) and `-8007` (Exception not handled) alert each
  appeared over the app during the round; both followed a bad `ns_eval`
  expression or a closed view's pending delayed call, not a defect in A7. Run a
  `2+2` sanity eval before believing anything, per the F1 round.

Tooling
-------
`scripts/newton-round.sh` now honours `NEWTON_INSTANCE`: it derives the
container name and the control URL, so a round can run against an isolated
instance instead of the shared emulator. All three builds this round used it
(`NEWTON_INSTANCE=f2round scripts/newton-round.sh examples/harness-client a7`),
and `--self-check` still passes.
