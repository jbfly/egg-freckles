On-device probes (runtime/ns_eval.py --instance e1ink):

  ClassOf(MakePolygon([10,10,50,50,90,10]))
    -> 'polygon
       (MakePolygon accepts a flat numeric array — no per-segment MakeLine.)

  begin local b := ShapeBounds(MakePolygon([0,0,100,10,0,20]));
        b.left & "/" & b.top & "/" & b.right & "/" & b.bottom end
    -> "0/0/101/21"
       (Read as x,y pairs: (0,0) (100,10) (0,20). Read as y,x it would have
       been 0/0/21/101. So MakePolygon takes X,Y — the reverse of
       GetPointsArray's Y,X. The swap is the whole conversion.)

  Coordinate space, measured with the probe build installed:
  drag 60 100 -> 200 160, then
  begin local a := GetRoot().|InkPad2:jbfly|.strokes[0];
        "y0=" & a[0] & " x0=" & a[1] & " n=" & Length(a) end
    -> "y0=100 x0=60 n=128"
       GetPointsArray really is screen-global, as the ref says. The probe build
       drew the retained polygon without subtracting the ink view's origin and
       the ink landed exactly +16,+54 down-right of the drag
       (e1ink-0-probe-offset.png) — that offset is the ink view's GlobalBox
       origin (app view left 8/top 24 + ink child left 8/top 30). Shipped code
       subtracts originLeft/originTop in StrokeShape.

  Open vs closed polygon, measured by injecting a bent stroke:
  GetRoot().|InkPad2:jbfly|:CountStroke([280,60,280,140,210,140], 16, 54)
    -> the canvas shows an open "L" (e1ink-4-polyline.png). No closing chord
       from the last vertex back to the first, so MakePolygon is safe for
       handwriting.

Still open (found here, not fixed here)
---------------------------------------
Encode() adds the ink view's origin to every point (examples/ink-capture/Main.newt,
"local x := points[1] + self.inkLeft"). The points are already screen-global —
measured above — so the NSI1 body the host renders is shifted +16,+54 and ink
near the bottom-right of the canvas can fall outside the 320x480 render. The
Send path was out of scope this session (no host, no network), so the encoder
was left untouched; fix it with E2/E3 when the POST path is exercised again.
