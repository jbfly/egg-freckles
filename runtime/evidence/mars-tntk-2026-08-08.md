# mars "tntk broken builds" — re-diagnosis, 2026-08-08

## Bottom line
The prior handoff's theory (mars's **tntk binary** is corrupt and emits a
968-byte stub) is **disproven by direct test**. Both the mars binary and the
dev-box binary build the real app source into byte-size-identical, launchable
packages. The genuine root cause of the -48809 launch failure is tntk's
**zero-exit-on-source-error** behavior (partial `package0` stub written despite
`Uncaught exception:`), and that is **already guarded** by commit `8d933fd`
("Reject partial tntk package builds"), which is deployed on mars.

The last row is decisive: the "corrupt" mars binary builds the real app to the
same 99096-byte package. Header `package0xxxx` is normal even for the good 99KB
package -- it is not a stub signature. A minimal toy source builds to ~1KB with
a clean (no-exception) tntk run on both boxes; that is a valid tiny package,
not the failure.

### Actual -48809 root cause (repo evidence: mars-agent-pkg-download-20260807.txt)
tntk emits `Uncaught exception: kNErrUndefinedVariable` (e.g. undefined
`CellButton`) but exits 0 and writes a partial `package0` stub. It installs into
the store but launches with -48809 -> agent retry loop -> 300s codex timeout ->
"agent timed out."

### Fix already deployed
`newton_mcp.py` `tool_build_pkg`:
`if code != 0 or "Uncaught exception:" in output or not pkg.exists(): -> build failed`.
Commit 8d933fd, regression test `test_build_pkg_does_not_publish_tntk_exception`.
`git merge-base --is-ancestor 8d933fd a49a1b9` = YES (live on mars).

## Live incident root cause: valid package, unsafe launch retry (2026-08-08)

A copied workspace rebuilt cleanly to another 8,336-byte package, and that

`|TicTacToeCPUR1:nwh|:Open();`. That sends `Open` to a symbol, not the
registered app template, and the next screenshot showed the exact `-48809`

### Why the build guard did not fire

It was not bypassed. The exact Codex rollout is
`~/.codex/sessions/2026/08/08/rollout-2026-08-08T05-31-08-019fe1ff-d865-7ad0-9117-0c810d06c52f.jsonl`
on mars. Its ordered response items show:

- item 80/83: `mcp__newton__build_pkg` returned the workspace path, emulator
  path, Loader filename, and `Package tic-tac-toe-cpu-r1.pkg created.`;
- item 94/97: `emulator_install` and the documented
  `GetRoot().|TicTacToeCPUR1:nwh|:Open();` were queued;
- items 99-135: four screenshots stayed on stock Notes while the agent retried;
- item 138/140: the agent issued the different expression
  `|TicTacToeCPUR1:nwh|:Open();`;
- item 145/147: the screenshot immediately changed to `Sorry, a problem has
  occurred. (-48809)` ([captured screen](mars-incident-unsafe-open-20260808.png),
  SHA-256 `63d2584cf39597349a73c9c82751b1d6f571f5e4c920d0679cb1a2b3e0f5a3a7`).

The current build path is `newton_mcp.py:517-542`: it rejects nonzero make,
literal `Uncaught exception:`, or a missing package, then stages a clean-output
package. This build met all three success conditions. The 300-second outer
failure is `server.py:609-614`; the Codex turn kept diagnosing/retrying until
that deadline. Therefore the precise incident classification is **(c)**: the
8,336-byte package is valid, and the observed `-48809` came from the later
launch/verification retry, not from tntk or staging.

passes `|TicTacToeCPUR1:nwh|:Open();`, asserts an error containing the safe
